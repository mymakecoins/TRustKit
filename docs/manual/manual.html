Manual Oficial de Uso do TRustKit

Guia operacional completo para desenvolvedores, arquitetos, lideres tecnicos e operadores agênticos. Aprenda a orquestrar os 7 Gates do Spec-Driven Development (SDD), isolamento em Git Worktrees, auditoria sintatica de Camada 0 e certificacao com Event Sourcing no SQLite WAL.

Versao: 1.0.0 Binario: trustkit Linguagem: Rust Nativo (6 Crates) Latencia AST: < 3ms Invariantes: 16 Regras

1. Visao Geral & Boas-Vindas

O TRustKit e uma plataforma deterministica voltada para fluxos de desenvolvimento orientados a especificacoes (Spec-Driven Development — SDD). Construido em Rust de alto rendimento, ele substitui rotinas interpretadas lentas por validacoes compiladas ultrarrapidas que executam em 1 a 3 milissegundos.

Velocidade Instantanea < 3ms

Validacao sintatica em microssegundos com parsers AST nativos do Tree-Sitter, sem cold-starts de runtime.

Zero Alucinacao Deterministico

Verificacao mecanica de fechamento de matrizes, integridade de testes e regras sintaticas sem depender de probabilidade de LLMs.

Paralelismo Seguro Git Worktrees

Execucao simultanea de tarefas em arvores de trabalho isoladas via Copy-on-Write (reflink), prevenindo corrupcao de indice.

Auditoria Imutavel SQLite WAL

Persistencia transacional imutavel (.trustkit/state.db) com selos criptograficos BLAKE3 de cada transicao de estado.

1.3 O Paradigma Hybrid Rust Core + Thin Skill

O TRustKit opera sob uma composicao equilibrada em duas camadas:

  • Thin Skill Declarativa (Prompt): Guia instrucional enxuta em Markdown que reside na memoria do agente/desenvolvedor para raciocinio de negocio sem sobrecarregar a janela de tokens.
  • Native Rust Core (Binario trustkit): Motor compilado responsavel por 100% das mutacoes fisicas de arquivos, git, verificacoes de TDD e hashes criptograficos.

Principios Constitucionais de Governanca

1. Sem Codigo Sem Spec Congelada: Nenhum commit de tarefa e autorizado sem selo BLAKE3 na especificacao.
2. Evidencia sobre Assercao: Testes sao homologados por comprovacao de saida de terminal e codigos POSIX reais.
3. Anti-Cheat de Testes: Expressamente proibido remover, enfraquecer assercoes ou pular testes (.skip).
4. Proibicao Absoluta de Emojis: Qualquer emoji em codigo, spec ou commit provoca reprovacao imediata.
5. Pull Request Sob Demanda: PRs sao abertos exclusivamente quando o desenvolvedor humano solicita.
6. Sem Trailers de IA: Vetado o uso de 'Co-Authored-By: Claude' ou rodapes gerados automaticamente.

2. Primeiros Passos

Configure e verifique o funcionamento do binario trustkit antes de iniciar suas demandas.

2.1 Compilacao e Instalacao

Terminal (Bash) 
# Compilar o workspace em modo release
cargo build --workspace --release

# Opcional: criar atalho global no sistema
sudo ln -sf "$(pwd)/target/release/trustkit" /usr/local/bin/trustkit

# Checar versao instalada
trustkit --version

2.3 Modos de Operacao: Humano vs Agente

O TRustKit suporta nativamente dois formatos de saida ergonomicos:

  • Modo Humano (Padrao): Apresenta tabelas limpas, texto legivel, prefixos padronizados como [PASS], [FAIL], [GATE-0] a [GATE-6] e o rodape contextual NEXT STEP: indicando os proximos comandos priorizados ([PRIMARY], [SECONDARY], [OPTIONAL]).
  • Modo Agente (Flag --json ou TRUSTKIT_AGENT_MODE=1): Retorna dados em JSON minificado, sem formatacao ANSI, sem valores nulos (null) e enriquecidos com o array next_steps calculado pelo NextStepResolver (priority, target_gate, command e description).

2.4 Consultando o Status da Sessao e o Proximo Passo

Terminal (Bash) 
trustkit status

[STATUS] Gate Atual: GATE_1_SPECIFICATION

  [SECONDARY] (GATE_2_LOCK) trustkit spec lock --spec docs/specs/issue-45-202611041030/spec.md
              -> Freeze the specification with a BLAKE3 seal once linting passes.

2.5 Guia de Adocao: Novo Projeto vs Projeto em Andamento

O TRustKit foi arquitetado para eliminar atritos operacionais: o proprio comando trustkit init inspeciona o ambiente, gera ou edita o .gitignore, provisiona o template trustkit.toml, inicializa o banco SQLite WAL e monta a infraestrutura do ciclo.

Cenario A: Projeto Novo Greenfield

Repositorio vazio, sem codigo pre-existente. Apos a boa pratica de configurar o Git e o remote, o comando unico do TRustKit cuida de todo o scaffolding.

Cenario B: Projeto Existente Brownfield

Repositorio com codigo e historico ativos. O TRustKit edita o .gitignore existente sem sobrescrever exclusoes anteriores, mapeia o grafo estrutural e diagnostica God Nodes.

Cenario A: Como Configurar o TRustKit em um Projeto Novo (Sem Codigo)

Siga o fluxo simplificado com a preparacao recomendada do repositorio e o comando unico de inicializacao:

Passo 1: Boa Pratica Previa de Repositorio (Git e Remote) 
# Criar diretorio e acessar
mkdir meu-novo-sistema && cd meu-novo-sistema

# Inicializar o Git com branch base e configurar remote de origem
git init -b develop
git remote add origin git@github.com:organizacao/meu-novo-sistema.git
git commit --allow-empty -m "chore: initial repository bootstrap"
Passo 2: Comando Unico de Inicializacao e Scaffolding 
# Se vinculado a uma issue do GitHub Projects:
trustkit init --issue 1

# Ou para ciclo puramente local (desconectado):
trustkit init
O que o trustkit init faz de forma 100% automatica:
  • Gerencia o .gitignore: Cria o arquivo ou anexa as regras essenciais (.trustkit/state.db*, .trustkit/worktrees/, .trustkit/audits/ e !.trustkit/wiki/) sem alterar regras existentes.
  • Gera o trustkit.toml: Cria o arquivo de governanca do Gauntlet caso ausente.
  • Provisiona a infraestrutura: Cria .trustkit/, inicializa o banco SQLite WAL com migrations e cria docs/specs/<ciclo>/.
Passo 3: Ativar os Fast Hooks no assistente agêntico 
# Configurar hook PreToolUse do assistente (Claude Code, Cursor, Antigravity):
trustkit hook pre-tool --command "$COMMAND"

Cenario B: Como Implantar o TRustKit em um Projeto em Andamento (Brownfield / Legado)

Para repositorios em producao com codigo existente (Rust, TypeScript, JavaScript, Python, etc.):

  1. Verificar status da arvore Git: O TRustKit tolera modificacoes locais sem comitar, registrando-as como pre_existing_dirty_files sem disparar git stash destrutivo. Apenas certifique-se de que a branch atual esta checkoutada (evite detached HEAD).
Passo 2: Inicializar o ciclo no projeto legado 
# Inicializa na issue ativa ou importando um PRD existente
trustkit init --issue 45 --from-prd docs/PRD_Legado.md
Edicao Automatica do .gitignore Existente
Se o repositorio brownfield ja tiver um .gitignore, o trustkit init nao o sobrescreve: ele detecta as regras faltantes e anexa o bloco do TRustKit ao final do arquivo, preservando integralmente suas exclusoes anteriores (ex: node_modules/, target/, .env). O mesmo ocorre com trustkit.toml, que so e criado se nao existir.
Passo 3: Gerar o Grafo Estrutural Imediato do Legado 
# Mapeia dependencias e emite .trustkit/wiki/graph/GRAPH_REPORT.md
trustkit graph build

# Diagnostica a saude do sistema e aponta os maiores God Nodes existentes
trustkit graph health --top-god-nodes 10
Passo 4: Ingerir notas de arquitetura na Memoria Perene 
# Registrar visao arquitetural do sistema legado
trustkit memory write --slug "arquitetura-legada" --title "Visao Geral do Legado" --tags "overview,brownfield" --body "Visao dos modulos e servicos..."

# Reconstruir indice SQLite FTS5 BM25
trustkit memory rebuild

Com o grafo e a memoria populados, o fatiador de contexto (trustkit context slice) e o gerador de spec (trustkit spec prompt) conseguem navegar cirurgicamente pelo codigo legado, evitando alucinacoes sobre arquivos existentes.

3. Guia Operacional Passo a Passo (Os 7 Gates do SDD)

Conheca o roteiro pratico para construir e entregar uma funcionalidade com qualidade absoluta.

Gate 0: Inicializacao do Ciclo e Setup de Contexto

Prepara a arvore de trabalho, valida a conta do GitHub e registra a sessao transacional.

Iniciar ciclo com Issue vinculada 
# Inicializa o ciclo vinculado a issue 45
trustkit init --issue 45

# Ou inicializa importando regras de um documento PRD funcional
trustkit init --issue 45 --from-prd docs/PRD_TRustKit.md

Acoes executadas automaticamente pelo comando:

  1. Valida credenciais do GitHub CLI e assegura que a conta corporativa esteja ativa.
  2. Inspeciona o Git e protege arquivos modificados pre-existentes contra perda acidental.
  3. Cria a pasta isolada de especificacao: docs/specs/issue-45-AAAAMMDDHHMM/.
  4. Transiciona o card para 'In progress' no GitHub Projects.
  5. Abre a sessao auditavel no SQLite WAL (.trustkit/state.db).

Gates 1 & 2: Especificacao V2, Linter e Selo Criptografico BLAKE3

Garante que todos os requisitos funcionais e fluxos de tela estejam blindados antes de programar.

Passo 1: Gerar o prompt e esqueleto da Spec 
trustkit spec prompt --idea "Autenticacao MFA via TOTP com codigos de recuperacao" --budget 4000
Passo 2: Executar Linter Estatico Pre-Lock (< 3ms) 
trustkit spec lint
Passo 3: Congelar a especificacao (Gate 2) 
trustkit spec lock
Fechamento da Matriz de Rastreabilidade
O comando spec lock valida matematicamente que cada Regra de Negocio (RN) possui correspondencia com um Requisito Funcional (RF), uma Tarefa (TASK), um Teste E2E e uma captura de tela (Screenshot). Se houver regras orfas, o congelamento e barrado.

Gate 3: Decomposicao Atomica e Planejamento de Ondas (DAG)

Valida os arquivos de tarefa em tasks/TASK-NNN.md e organiza a ordem de execucao sem conflitos.

Compilar DAG e Planejar Ondas 
trustkit wave plan

O planejador analisa dependencias declaradas e assegura que tarefas que modifiquem os mesmos arquivos fiquem em ondas separadas.

Gate 4: Execucao em Git Worktrees e TDD Mecanico (RED -> GREEN -> REFACTOR)

Implementa cada tarefa com protecao física de arvore e exigencia de prova de falha previa.

1. Despachar onda de trabalho 
trustkit wave run --wave 1
2. Comprovar Fase RED (Falha do teste) 
trustkit task test TASK-001 --phase red
3. Implementar codigo e comprovar Fase GREEN (Sucesso do teste) 
trustkit task test TASK-001 --phase green
4. Revisao Semantica de Codigo (Refactor) e Conclusao 
# Revisao semantica multi-angulo
trustkit task review TASK-001 --effort medium

# Homologar e comitar a tarefa
trustkit task complete TASK-001

Gate 5: Gauntlet Loop V2 e Revisao de Seguranca

Auditoria profunda dividida em duas camadas deterministas com suporte a revisao de seguranca de aplicacao.

Camada 0: AST Audit em Microssegundos 
trustkit gauntlet ast-audit
Camada 1: Gauntlet Swarm, Playwright E2E e Security Review 
# Execucao padrao com pergunta interativa de seguranca
trustkit gauntlet run

# Ou forçando a execucao da revisao de seguranca do diff
trustkit gauntlet run --security-review

# Ou dispensando explicitamente a revisao de seguranca
trustkit gauntlet run --skip-security-review
Disjuntor de Seguranca (Circuit Breaker)
Caso a bateria do Gauntlet seja reprovada por 5 vezes consecutivas, o sistema aciona o disjuntor para evitar loops infinitos. Para investigar as causas, utilize trustkit doctor.

Gate 6: Certificacao Oficial, Merge e Pull Request

Finaliza o ciclo gerando o dossie de evidencias e realizando a integracao controlada.

1. Certificar e gerar gauntlet-report.md 
trustkit done
2. Realizar o merge deterministico para branch alvo 
trustkit merge --target develop
3. Abrir Pull Request sob demanda humana 
trustkit pr --target develop

Exemplo Pratico: Ciclo Completo de Feature com 3 Waves

Abaixo esta demonstrada a sequencia deterministica exata de comandos para executar uma funcionalidade do inicio ao fim (Gate 0 ao Gate 6), considerando um plano decomposto em 3 waves topologicas no DAG:

  • Onda 1 (Base e contratos): TASK-001 (Core Domain) e TASK-002 (Adaptador de Persistencia)
  • Onda 2 (Regra de negocio / Servicos): TASK-003 (Servico de Autenticacao / Dominio)
  • Onda 3 (Interface e bordas): TASK-004 (Handlers CLI / Integracao)

Gate 0: Inicializacao do Ciclo e Setup de Ambiente

Valida a identidade GitHub, protege arquivos pre-existentes na arvore Git e inicializa a sessao no banco transacional SQLite WAL:

Inicializar ciclo associado a issue 
trustkit init --issue 42

Gate 1: Formulacao e Validacao da Especificacao (Spec V2)

Gera o esqueleto estruturado da especificacao e valida continuamente as regras constitucionais via linter estatico antes do congelamento:

Scaffolding estruturado e linter imediato 
# 1. Gera o prompt estruturado e o esqueleto de spec.md com contexto fatiado da AST e da wiki
trustkit spec prompt --idea "Implementar modulo de autenticacao multifator TOTP" --budget 4000

# 2. Executa o linter estatico imediato para validar Gherkin, Mermaid e matriz de rastreabilidade
trustkit spec lint

Gate 2: Congelamento Criptografico (Spec Lock)

Sela a especificacao com digest BLAKE3 apos validacao completa da Matriz de Rastreabilidade ponta a ponta (RN -> RF -> TASK -> E2E):

Selo criptografico BLAKE3 
trustkit spec lock

Gate 3: Decomposicao e Planejamento Topologico em Ondas (DAG)

Apos a elaboracao das tarefas atomicas em tasks/TASK-NNN.md, compila o grafo de dependencias e calcula as 3 ondas de execucao paralela:

Compilar DAG e ondas de tarefas 
trustkit wave plan

Gate 4: Execucao das 3 Ondas com Git Worktrees e TDD Estrito

Cada tarefa atomica e isolada em uma Git Worktree dedicada (.trustkit/worktrees/) e deve cumprir obrigatoriamente o ciclo TDD: RED comprovado antes de GREEN.

Execucao da Onda 1
Onda 1: Despachar worktrees e ciclo TDD 
# 1. Despacha e provisiona os worktrees isolados da Onda 1
trustkit wave run --wave 1

# --- Execucao da TASK-001 ---
# Registra comprovacao obrigatoria de falha do teste (fase RED)
trustkit task test TASK-001 --phase red

# Apos codificar a solucao, registra comprovacao obrigatoria de sucesso (fase GREEN)
trustkit task test TASK-001 --phase green

# Revisao semantica multi-angulo do diff antes da conclusao (fase REFACTOR)
trustkit task review TASK-001 --effort medium

# Conclui a tarefa atomica e integra na branch de trabalho da feature
trustkit task complete TASK-001

# --- Execucao da TASK-002 ---
trustkit task test TASK-002 --phase red
trustkit task test TASK-002 --phase green
trustkit task review TASK-002 --effort medium
trustkit task complete TASK-002
Execucao da Onda 2
Onda 2: Despachar worktrees e ciclo TDD 
# 2. Despacha os worktrees da Onda 2 (dependentes da conclusao da Onda 1)
trustkit wave run --wave 2

# --- Execucao da TASK-003 ---
trustkit task test TASK-003 --phase red
trustkit task test TASK-003 --phase green
trustkit task review TASK-003 --effort medium
trustkit task complete TASK-003
Execucao da Onda 3
Onda 3: Despachar worktrees e ciclo TDD 
# 3. Despacha os worktrees da Onda 3 (dependentes da conclusao da Onda 2)
trustkit wave run --wave 3

# --- Execucao da TASK-004 ---
trustkit task test TASK-004 --phase red
trustkit task test TASK-004 --phase green
trustkit task review TASK-004 --effort medium
trustkit task complete TASK-004

Gate 5: Gauntlet Loop V2 (Auditoria AST e Swarm de Criticos)

Executa a esteira de validacao adversarial mais rigorosa do sistema:

Auditoria AST e Swarm de Criticos 
# 1. Camada 0: Inspecao AST sintatica (< 5ms) via Tree-Sitter (anti-cheat, zero emojis, sem trailers de IA)
trustkit gauntlet ast-audit

# 2. Camada 1: Suite de testes de integracao, build release, Playwright E2E e swarm de criticos
trustkit gauntlet run

Gate 6: Certificacao, Merge e Abertura de Pull Request Sob Demanda

Consolida as evidencias, integra o codigo na branch alvo e publica o PR apenas sob demanda humana explicita:

Certificacao, merge e PR sob demanda 
# 1. Consolida o relatorio oficial gauntlet-report.md e publica comentario na issue
trustkit done

# 2. Realiza o merge deterministico na branch de destino (ex: develop) e limpa a branch de feature
trustkit merge --target develop

# 3. Abre o Pull Request formal no repositorio (somente sob solicitacao humana explicita)
trustkit pr --target develop

3.8 Orquestracao Autonoma de Ponta a Ponta (trustkit auto v2.2)

Para fluxos em que os requisitos ja foram formulados ou a especificacao formal ja esta pronta, a versao 2.2 do comando unificado trustkit auto orquestra todos os 7 gates (0 ao 6) de forma 100% deterministica, com atomizacao automatica, verificador TDD rigoroso e merge cumulativo seguro:

  • Gate 0 (Setup & Init): Inspeciona identidade Git, branches e baseline limpo, inicializando no SQLite WAL.
  • Gate 1 (Spec Lint): Valida o linter nativo AST em microssegundos (sem emojis, Gherkin e matriz fechada).
  • Gate 2 (Spec Lock): Sela a especificacao congelada com hash BLAKE3 criptografico.
  • Gate 3 (Wave Plan & Atomizacao): Atomiza deterministicamente a especificacao ou issue se tasks/ nao existir, dispara o disjuntor EmptyTaskBacklogFault se houver zero tarefas e calcula as ondas DAG.
  • Gate 4 (Multi-Wave TDD Loop & Builder Dispatch): Sintetiza testes RED compilaveis (RedTestScaffolder), bloqueia filtros vazios e erros de compilacao mascarados, despacha agentes construtores e executa merge seguro sem force reset.
  • Gate 5 (Gauntlet V2): Executa auditoria Camada 0 e consolida vereditos dos criticos adversariais, de contrato, estaticos e Playwright.
  • Gate 6 (Certify & Merge): Emite gauntlet-report.md, atualiza o board e realiza merge deterministico na branch alvo.
A partir de uma issue remota do GitHub 
trustkit auto --issue 45 --target develop
A partir de um arquivo local de especificacao 
trustkit auto --spec docs/specs/minha-feature/spec.md --target develop
Modo Agente com saida JSON determinista (livre de null) 
trustkit auto --spec docs/specs/minha-feature/spec.md --target develop --runtime native --json

4. Recursos Avancados e Modulos Especializados

4.1 Memoria Perene do Projeto (trustkit memory)

Gerencia a base de documentacao viva estruturada em Markdown sob .trustkit/wiki/, com indexacao FTS5 BM25 e suporte a [[wikilinks]].

Comandos de Memoria
# Buscar documentos por termo semantico
trustkit memory search --query "diretrizes de testes" --limit 5

# Ler uma nota de documentacao
trustkit memory read --slug "architecture-decision-001"

# Registrar nova nota na memoria perene
trustkit memory write --slug "padroes-auth" --title "Padroes Auth" --tags "auth,jwt" --body "Texto..."

# Listar todas as notas cadastradas
trustkit memory list

# Reconstruir o indice FTS5 a partir dos arquivos
trustkit memory rebuild

4.2 Inteligencia de Grafo Estrutural (trustkit graph)

Mapeia dependencias sintaticas de codigo (funcoes, imports, structs) e notas wiki com deteccao automatica de componentes hiperacoplados (God Nodes).

Comandos de Grafo
# Construir ou atualizar o grafo estrutural (emite GRAPH_REPORT.md)
trustkit graph build

# Diagnosticar a saude do grafo e componentes criticos
trustkit graph health --top-god-nodes 5

# Encontrar menor caminho de chamadas entre dois simbolos via BFS
trustkit graph path --source "crates/trustkit-core::SddCycle" --target "crates/trustkit-db::SqliteWalRepositoryAdapter"

# Explicar relacoes e dependencias de um componente
trustkit graph explain --node "crates/trustkit-core/src/entities.rs::SddCycle"

4.3 Fatiamento Cirurgico de Contexto (trustkit context)

Extrai apenas as assinaturas, interfaces e tipos necessarios para alimentar prompts de IA sem exceder janelas de contexto.

Exemplos de Fatiamento
# Fatiamento classico por arquivo com orcamento de tokens
trustkit context slice --file crates/trustkit-core/src/lib.rs --budget 500

# Fatiamento multi-hop guiado pelo grafo estrutural (BFS)
trustkit context slice --file crates/trustkit-core/src/entities.rs --hops 2 --strategy bfs --budget 800

4.4 Protecao Proativa com Fast Hooks (trustkit hook)

Interceptador de chamadas shell que atua em menos de 3 milissegundos para barrar acoes proibidas.

Execucao de Hook
trustkit hook pre-tool --command "git add ."

Comandos destrutivos como git stash, git reset --hard ou commits contendo emojis sao interceptados antes da execucao.

4.5 Servidor Nativo MCP (trustkit mcp)

Disponibiliza ferramentas deterministas via Model Context Protocol para clientes compativeis (Claude Code, Cursor, Antigravity).

Inicializar Servidor MCP

5. Perguntas Frequentes (FAQ)

O que acontece se eu precisar alterar uma regra de negocio apos o Gate 2?
Uma vez selada a especificacao, qualquer mudanca manual em spec.md viola a assinatura BLAKE3 e impede novos commits. Para atualizar requisitos, execute uma revisao formal que atualize os hashes e valide a Matriz de Rastreabilidade.
Posso rodar tarefas em paralelo sem risco de conflito no Git?
Sim. O comando wave run cria arvores de trabalho fisicamente isoladas (Git Worktrees efemeras). Cada tarefa possui seu proprio diretorio de trabalho, prevenindo conflitos em .git/index ou dependencias.
Por que o Pull Request nao abre automaticamente ao final do Gate 6?
A Invariante #12 proibe a abertura autonoma de Pull Requests. A decisao de submeter o trabalho para integracao em branches estaveis pertence exclusivamente ao desenvolvedor humano responsavel via comando trustkit pr.
Como o TRustKit se comporta se nao houver uma issue no GitHub?
O sistema opera no padrao de Caso Especial (UnlinkedLocalCycle). Voce podera executar todos os 7 gates e testes localmente sem qualquer bloqueio ou chamada de rede desnecessaria.

6. Guia de Solucao de Problemas (Troubleshooting)

6.1 Codigos de Saida Semanticos (POSIX)

Codigo Identificador Causa Acao Recomendada
0 CleanPass Operacao concluida com aprovacao. Avancar para o proximo gate do ciclo.
1 InfrastructureBoundaryFault Erro de I/O em disco, SQLite WAL, Git ou disjuntor de tarefas vazias (EmptyTaskBacklogFault). Verificar permissoes de escrita, espaco em disco ou revisar itens acionaveis na especificacao.
2 SpecOrTraceabilityIncomplete Spec incompleta ou lacuna na matriz. Executar trustkit spec lint e cobrir regras orfas.
3 TddLifecycleViolation Tentativa de GREEN sem RED comprovado, filtro vazio (ZeroFilteredTestsFault) ou erro de compilacao no RED (CompilationFailureInRedPhaseFault). Garantir teste compilavel que falhe exclusivamente por assercao de dominio na fase red.
4 AstIntegrityOrInvariantViolation Emojis, trailers IA ou alteracao de testes. Executar trustkit gauntlet ast-audit para diagnostico.
5 CriticSwarmOrPlaywrightFailed Falha de compilacao, linter ou E2E. Inspecionar relatorio de testes e corrigir falhas de codigo.
6 CircuitBreakerTripped Disjuntor disparado apos 5 falhas seguidas. Executar trustkit doctor e corrigir as causas apontadas.

6.2 Diagnostico com o Assistente Doutor

Caso o ciclo seja interrompido ou ocorram falhas acumuladas, invoque o diagnosticador:

Executar Diagnostico
trustkit doctor

7. Glossario de Termos e Linguagem Ubiqua

Termo Ubiquo Definicao no TRustKit
SddCycle Instancia de execucao isolada e auditavel correspondente a entrega de uma funcionalidade.
GateStage Cada um dos 7 marcos deterministas que governam a progressao do ciclo de desenvolvimento.
ArtifactSeal Selo criptografico BLAKE3 que assegura a integridade imutavel da especificacao no Gate 2.
TraceabilityLink Amarra verificavel entre Regra de Negocio, Requisito Funcional, Tarefa, Teste E2E e Screenshot.
AtomicTask Unidade minima de implementacao restrita a uma camada arquitetural e sujeita ao ciclo TDD.
ExecutionWave Conjunto de tarefas independentes entre si despachadas simultaneamente em Git Worktrees.
CircuitBreaker Disjuntor de seguranca acionado apos a 5ª reprovacao consecutiva na esteira do Gauntlet.
Modo Agente Execucao do CLI via flag --json com saida estritamente livre de campos nulos (null).
Thin Skill Guia instrucional conciso em Markdown que orienta raciocinios de alto nivel no contexto do agente sem invalidar o KV-Cache.
Slash Commands SDD Conjunto de comandos conceituais (/sdd-define, /sdd-planning, /sdd-execute, etc.) que padronizam o fluxo SDD.
Gauntlet Loop V2 Bateria de verificacao adversarial multi-agente que audita integridade estatica, TDD, Playwright E2E e seguranca antes do merge.
