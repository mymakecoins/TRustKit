# Thin Skill Declarativa: TRustKit (v4)

Esta skill orquestra o ciclo de vida do SDD delegando todas as validações determinísticas, isolamento de Worktrees, fiscalização de TDD e transições de Gates ao binário nativo `trustkit`.

## Invariantes Obrigatórios

1. Proibição absoluta de emojis ou ícones Unicode em qualquer arquivo ou commit.
2. Proibição absoluta de trailers de autoria IA (ex: Co-Authored-By, Generated by).
3. Toda mutação de estado e validação de invariantes deve ser executada pelo binário `trustkit`.
4. Os testes do Gate 4 devem seguir estritamente o ciclo TDD: RED comprovado antes de GREEN.
5. Abertura de Pull Request ocorre exclusivamente sob demanda humana explícita.

## Jornada dos Gates

### Gate 0: Inicialização do Ciclo
Execute a inicialização para validar identidade, branches e registrar a sessão:
```bash
trustkit init --issue <ISSUE_ID> [--from-prd <CAMINHO_PRD>] --json
```

### Gate 1 & 2: Especificação e Congelamento (Spec Lock)
Elabore o arquivo de especificação (`spec.md`) com Mermaid, Gherkin e Matriz de Rastreabilidade. Congele a especificação com selo BLAKE3:
```bash
trustkit spec lock --json
```

### Gate 3: Tarefas Atômicas e Planejamento de Ondas
Elabore as tarefas atômicas em `tasks/TASK-NNN.md` e planeje o DAG de ondas paralelas:
```bash
trustkit wave plan --json
```

### Gate 4: Execução em Git Worktrees e TDD Estrito
Execute as tarefas da onda com isolamento de worktree e garanta as fases TDD:
```bash
# Executa a onda com isolamento de worktree
trustkit wave run --wave <WAVE_INDEX> --json

# Registra a fase RED (falha obrigatória comprovada)
trustkit task test <TASK_ID> --phase red --json

# Registra a fase GREEN (sucesso obrigatório comprovado)
trustkit task test <TASK_ID> --phase green --json

# Conclui a tarefa atômica
trustkit task complete <TASK_ID> --json
```

### Gate 5: Gauntlet V2 (Auditoria AST e Swarm de Críticos)
Execute a auditoria léxica/AST da Camada 0 e os críticos da Camada 1:
```bash
# Camada 0: Scanner léxico, invariantes, ausência de emojis e integridade de asserções
trustkit gauntlet ast-audit --json

# Camada 1: Swarm de críticos concorrentes e guardião de evidências visuais
trustkit gauntlet run --json

# Diagnóstico caso o disjuntor (Circuit Breaker) seja acionado após falhas
trustkit doctor --json
```

### Gate 6: Certificação, Merge e Pull Request Sob Demanda
Gere o relatório oficial de certificação, faça o merge e abra o PR sob demanda:
```bash
# Consolida evidências e gera gauntlet-report.md
trustkit done --json

# Executa merge determinístico para a branch alvo
trustkit merge --target develop --json

# Abre Pull Request no GitHub Projects (apenas sob demanda do usuário)
trustkit pr --target develop --json
```

## Códigos de Saída Semânticos (POSIX Exit Codes)

| Código | Categoria | Descrição |
|---|---|---|
| 0 | CleanPass | Operação concluída com sucesso e aprovada em todos os gates. |
| 1 | InfrastructureBoundaryFault | Falha de I/O, banco de dados SQLite WAL, Git ou rede. |
| 2 | SpecOrTraceabilityIncomplete | Falha de sintaxe Mermaid/Gherkin ou spec não congelada. |
| 3 | TddLifecycleViolation | Tentativa de GREEN sem RED prévio, ou gap de rastreabilidade. |
| 4 | AstIntegrityOrInvariantViolation | Emojis detectados, trailers de IA ou ciclos no grafo DAG. |
| 5 | CriticSwarmOrPlaywrightFailed | Reprovação por crítico do Gauntlet ou falha em teste E2E. |
| 6 | CircuitBreakerTripped | Disjuntor acionado após 5 falhas consecutivas no Gauntlet. |
