## 1. Overview

TRustKit is a deterministic execution and governance platform built for Spec-Driven Development (SDD) workflows in high-density agentic environments (Claude Code, Antigravity, Codex) and high-performance software engineering teams.

The project resolves critical bottlenecks found in purely declarative approaches (Markdown skills) and legacy harnesses in interpreted runtimes (Python/Node.js):
- Dramatic latency reduction: replaces 300ms-2,000ms cold-start overheads with native compiled Rust validations executing in 1 to 3 milliseconds.
- Elimination of compliance hallucinations: mechanical validation of syntactic rules, test integrity, project invariants, and graph topology without relying on probabilistic LLM judgment.
- Safe parallelism via Git Worktrees: isolates multiple builder agents across independent worktrees with Copy-on-Write (reflink) support, preventing index corruption and race conditions.
- Immutable auditability via Event Sourcing: transactional persistence in SQLite WAL mode (`.trustkit/state.db`) recording every state transition, execution proof, and BLAKE3 cryptographic hash.
- Persistent Project Knowledge Memory: live documentation wiki (`.trustkit/wiki/`) indexed with SQLite FTS5, BM25 semantic ranking, and bidirectional `[[slug]]` wikilinks.
- Structural Graph Intelligence: AST syntactic extraction via Tree-Sitter for code symbols and architectural edges, multi-hop context slicing (BFS/DFS), wave coupling analysis, and God Node detection.
- Deterministic Contextual Next-Step Guidance (`NextStepResolver`): after every CLI command and in `trustkit status`, the engine evaluates the active cycle state in SQLite WAL and emits actionable next-step instructions both in ASCII (`NEXT STEP:`) and in null-free JSON (`next_steps`).

### The Hybrid Rust Core + Thin Skill Paradigm

TRustKit operates under a hybrid architecture:
- Declarative Thin Skill: a minimal Markdown layer (`SKILL.md`) residing in orchestrator agent context to steer high-level product and design decisions without wasting tokens or invalidating KV-Cache.
- Native Rust Core: the static binary `trustkit`, handling 100% of state mutations, Layer 0 AST verification, BLAKE3 cryptographic sealing, structural graph extraction, Git Worktree provisioning, and GitHub Projects synchronization.

## 2. Mandatory Governance Invariants

All operations managed by TRustKit strictly adhere to project constitutional invariants:
1. Absolute prohibition of emojis or graphical icons in any file, documentation, terminal output, or commit.
2. Absolute prohibition of AI-generated attribution trailers (such as `Co-Authored-By` or `Generated by`).
3. All state mutations and invariant evaluations must be executed exclusively by the `trustkit` binary.
4. Gate 4 tests must strictly follow the mechanical TDD lifecycle: proven RED phase (verified failure) mandatory prior to GREEN phase (verified pass).
5. Pull Request creation occurs exclusively upon explicit human developer request.
6. Direct pushes to protected branches (`main`, `staging`, `develop`) by autonomous agents are strictly prohibited (RN-006).

## 4. The 7-Gate SDD Lifecycle

The software development lifecycle is governed by 7 deterministic gates:

```
[Gate 0] Session Setup & Identity Verification
    |
[Gate 1] Context Slicing & Specification V2 (spec.md with Mermaid & Gherkin)
    |
[Gate 2] Cryptographic Spec Freezing (BLAKE3 Seal) & Knowledge Memory Ingestion
    |
[Gate 3] Atomic Task Decomposition & DAG Wave Planning with Coupling Analysis
    |
[Gate 4] Parallel Execution in Git Worktrees + Strict TDD Lifecycle (RED -> GREEN -> REFACTOR / Code Review)
    |
[Gate 5] Gauntlet V2 (Layer 0 AST Audit + Layer 1 Critic Swarm + Optional Security Review)
    |
[Gate 6] Official Certification, On-Demand Security Review, Deterministic Merge, and Pull Request
    |
[Pre-Release] Global 6-Phase Defensive Security Audit (trustkit audit security)
```

### End-to-End Autonomous Execution (`trustkit auto`)
For 100% autonomous execution of the entire SDD lifecycle (Gates 0 to 6) from a remote GitHub issue or local specification:
```bash
# Execute full deterministic cycle from a remote GitHub issue
trustkit auto --issue <ISSUE_ID> [--target develop] [--runtime auto|pty|native] [--json]

# Execute full deterministic cycle from a local specification file
trustkit auto --spec <SPEC_PATH> [--target develop] [--runtime auto|pty|native] [--json]
```

### Gate 0: Cycle Initialization
Validates GitHub profile identity, branches, working tree cleanliness, and initializes session state in SQLite:
```bash
trustkit init --issue <ISSUE_ID> [--from-prd <PRD_PATH>] [--json]
```

### Gate 1 & 2: Native Specification, Linting & Cryptographic Freezing (Spec Lock)
TRustKit is 100% self-contained for natural language specification authoring without depending on the external SDD ecosystem:
```bash
# Generate structured prompt with AST context slicing and living memory FTS5 search
trustkit spec prompt --idea "<FEATURE_DESCRIPTION>" [--context-hops 2] [--budget 4000] [--json]

# Execute sub-3ms static linter for pre-lock validation and agentic self-correction
trustkit spec lint [--file <SPEC_PATH>] [--json]

# Initialize specification from upstream PRD
trustkit spec init --from-prd <PRD_PATH> [--name <SLUG>] [--json]

# Freeze specification and apply BLAKE3 cryptographic seal
trustkit spec lock [--spec <SPEC_PATH>] [--json]
```

### Gate 3: Atomic Tasks & DAG Wave Planning
Validates atomic task files (`tasks/TASK-NNN.md`), inspects topological coupling and God Nodes, constructs the Directed Acyclic Graph (DAG), and calculates parallel execution waves:
```bash
trustkit wave plan [--json]
```

### Gate 4: Git Worktree Execution, Terminal Multiplexing, and Strict TDD
Executes tasks in parallel across isolated worktrees, orchestrates interactive builder agents via pseudoterminals (PTY multiplexer or native fallback), enforces strict TDD compliance (`RED -> GREEN`), and integrates multi-angle semantic code review into the `REFACTOR` phase:
- Fork-free integration with PTY multiplexer: communication over OpenRPC JSON-RPC 2.0 via Unix Domain Sockets for headless PTY control and persistent background agent sessions.
- Native OSC 7501 telemetry: deterministic emission of operational states (`working`, `blocked`, `done`, `error`) and execution progress compatible with Ghostty VT parsers.
- Terminal buffer sanitizer: strips residual ANSI sequences, enforces zero emojis (Principle VII), purges AI authoring trailers, and automatically redacts secrets.
- Native MCP monitoring tools: `trustkit_wave_status`, `trustkit_terminal_inspect`, and `trustkit_terminal_send` to inspect buffers and unblock interactive agents directly from the MCP client.

```bash
# Dispatch execution wave in isolated worktrees with runtime selector (auto, pty, native)
trustkit wave run --wave <WAVE_INDEX> [--runtime auto|pty|native] [--agent-cmd "<cmd>"] [--json]

# Record mandatory RED phase (proven test failure)
trustkit task test <TASK_ID> --phase red [--json]

# Record mandatory GREEN phase (proven test success after implementation)
trustkit task test <TASK_ID> --phase green [--json]

# Run multi-angle semantic code review in the REFACTOR phase (low, medium, high, max)
trustkit task review <TASK_ID> [--effort medium] [--json]

# Complete and homologate the atomic task (optionally triggering inline code-review)
trustkit task complete <TASK_ID> [--code-review medium] [--json]
```

### Gate 5: Gauntlet Loop V2 and Optional Security Review
Two-layer verification pipeline protecting the repository against regressions and invariant violations, paired with an optional user-governed application security diff review (`security-review`):
- Layer 0 (Native Microsecond AST Audit): anti-cheat test assertion checks, syntactic integrity, zero emojis, zero AI trailers, and detection of forbidden `any` or `raw.githubusercontent` patterns.
- Layer 1 (Concurrent Critic Swarm): release build verification, linter analysis, Playwright E2E suites, and domain/contract critics.
- Optional AppSec Layer (`security-review`): branch diff security analysis targeting high-confidence exploitable vulnerabilities (`>= 8/10`) with anti-false-positive filtering. Controlled via CLI flags (`--security-review` or `--skip-security-review`), interactive TTY prompt (`[s/N]`, default `N`), or declarative policy in `trustkit.toml`.
- Circuit Breaker: automatic execution halt tripped after 5 consecutive Gauntlet rejections.

```bash
# Run Layer 0 AST and static syntax audit
trustkit gauntlet ast-audit [--json]

# Full Gauntlet execution (prompts [s/N] on interactive TTY when applicable)
trustkit gauntlet run [--json]

# Explicitly force or skip the specialized branch diff security review
trustkit gauntlet run --security-review [--json]
trustkit gauntlet run --skip-security-review [--json]

# Diagnose failures and inspect Circuit Breaker state
trustkit doctor [--json]
```

Optional declarative configuration in `trustkit.toml`:
```toml
[governance.gauntlet]
# Modes: "prompt" (interactive terminal prompt), "always" (always run), "disabled" (never prompt)
security_review_mode = "prompt"
min_confidence_threshold = 8
```

### Gate 6: Certification, Merge, and Pull Request
Consolidates verification evidence into `gauntlet-report.md` (recording the security review status or allowing on-demand execution if skipped at Gate 5), performs a deterministic merge into the target branch, and opens a Pull Request upon explicit command:
```bash
# Certify session and compile final report (supports security-review flags)
trustkit done [--security-review | --skip-security-review] [--json]

# Perform deterministic merge into target branch
trustkit merge --target develop [--json]

# Open Pull Request (strictly upon human authorization)
trustkit pr --target develop [--json]
```

### Pre-Release Homologation: Global Defensive Security Audit (`audit security`)
For release milestones or before merging into stable branches (`staging` or `main`), TRustKit provides a decoupled 6-phase defensive security audit subcommand with deterministic ledger validation (`coverage-ledger.json` and `findings.json`):
```bash
# Execute global pre-release security audit (profiles: quick, standard, deep)
trustkit audit security [--profile standard] [--scope .] [--output-dir .trustkit/audits/security] [--json]
```

## 5. Persistent Project Knowledge Memory (`trustkit memory`)

TRustKit's persistent memory subsystem manages a structured Markdown wiki with YAML frontmatter in `.trustkit/wiki/`:

- SQLite Full-Text Search (FTS5) index with BM25 ranking for sub-millisecond retrieval.
- Bidirectional wikilink resolution using `[[slug]]` or `[[slug|Alias]]` syntax.
- Automated ingestion of Gauntlet incident postmortems and approved product specifications.
- Available subcommands:
  ```bash
  # Full-text semantic search across knowledge wiki
  trustkit memory search --query "invariants policy" [--limit 5] [--json]

  # Read note with frontmatter metadata and adjacent backlinks
  trustkit memory read --slug "architecture-decision" [--json]

  # Atomically create or update knowledge document
  trustkit memory write --slug "new-standards" --title "New Standards" --tags "core,guidelines" --body "Content..." [--json]

  # List all documents in persistent memory
  trustkit memory list [--json]

  # Rebuild entire FTS5 index from markdown files on disk
  trustkit memory reindex [--json]
  ```

## 6. Structural Graph Intelligence (`trustkit graph`)

The graph engine extracts and maintains a complete dependency topology spanning source code and documentation:

- Tree-Sitter syntactic extraction for Rust (modules, structs, traits, enums, public functions, and use declarations) and TypeScript/JavaScript (exports, imports, interfaces, classes, and functions).
- Unified graph blending code entities with wiki knowledge notes (`[[slug]]`).
- Strongly-typed relations: `Calls`, `Imports`, `Defines`, `Implements`, `WikiLinksTo` with confidence classification (`Extracted` vs `Inferred`).
- Shrink-Guard protection mechanism with BLAKE3 manifests preventing accidental node reduction without `--force`.
- Available subcommands:
  ```bash
  # Build or update structural graph and emit .trustkit/wiki/graph/GRAPH_REPORT.md
  trustkit graph build [--force] [--update] [--json]

  # Audit graph health, identify God Nodes, and flag architectural boundary violations
  trustkit graph health [--top-god-nodes 10] [--json]

  # Find shortest path (hop count) between two graph nodes via BFS
  trustkit graph path --source "src/lib.rs::SddCycle" --target "crates/trustkit-db::SqliteWalRepositoryAdapter" [--undirected] [--json]

  # Explain structural neighborhood, dependencies, and wiki notes for a specific node
  trustkit graph explain --node "crates/trustkit-core/src/entities.rs::SddCycle" [--json]
  ```

## 7. Context Slicing & Fast Hooks

### AST & Graph-Guided Context Slicing
Prunes and packages relevant code definitions to feed builder agent prompts without exhausting token budgets:
```bash
# Classic single-file signature slicing with token budget
trustkit context slice --file crates/trustkit-core/src/lib.rs --budget 500 [--json]

# Multi-hop graph-guided slicing (BFS or DFS traversal)
trustkit context slice --file crates/trustkit-core/src/entities.rs --hops 2 --strategy bfs --budget 600 [--json]
```

### Pre-Tool & Post-Tool Fast Hooks (< 3ms)
Synchronously intercepts agent tool calls to block destructive actions before execution:
```bash
trustkit hook pre-tool --command "<COMMAND>" [--json]
```
Automatically blocks:
- Destructive Git operations (`git stash`, `git reset --hard`, `git clean -fd`).
- Sweeping staging additions (`git add .`, `git add -A`).
- Unauthorized direct pushes to protected branches (`git push origin develop`).
- Autonomous Pull Request creation without `trustkit pr`.
- Unicode emojis or AI attribution trailers in commit messages.

## 12. Semantic POSIX Exit Codes

| Exit Code | Identifier | Category | Description |
|---|---|---|---|
| 0 | CleanPass | Success | Operation completed successfully, satisfying all quality gates. |
| 1 | InfrastructureBoundaryFault | Infrastructure Fault | Disk I/O error, SQLite WAL failure, Git command failure, or network fault. |
| 2 | SpecOrTraceabilityIncomplete | Specification Defect | Spec not frozen, Mermaid/Gherkin syntax error, or traceability gap. |
| 3 | TddLifecycleViolation | TDD Lifecycle Defect | Attempting GREEN without verified RED, or test assertions bypassed. |
| 4 | AstIntegrityOrInvariantViolation | Invariant Breach | Emojis detected, AI trailers present, DAG cycles found, or test dilution. |
| 5 | CriticSwarmOrPlaywrightFailed | Gauntlet Rejection | Compilation failure, linter warning, Playwright E2E failure, or critic rejection. |
| 6 | CircuitBreakerTripped | Circuit Breaker Tripped | Safety shutdown triggered after 5 consecutive Gauntlet rejections. |

## 13. Dual-Audience Operating Modes & Contextual Next-Step Guidance (`NextStepResolver`)

- Human Mode (standard TTY terminal output):
  - Pure ASCII textual layout with no emojis or decorative glyphs.
  - Standardized diagnostic prefixes: `[GATE-0]` to `[GATE-6]`, `[PASS]`, `[FAIL]`, `[WARN]`, `[INFO]`.
  - Standardized `NEXT STEP:` footer at the end of every command and in `trustkit status`, presenting prioritized recommendations (`[PRIMARY]`, `[SECONDARY]`, `[OPTIONAL]`) with target gates and exact commands.
  - Aligned tables and concise executive summaries.

- Agent Mode (`--json` flag or `TRUSTKIT_AGENT_MODE=1` environment variable):
  - Strict deterministic JSON without superfluous whitespace.
  - Guaranteed 100% null-free payloads (empty arrays `[]` and typed Special Case models).
  - Structured `next_steps` array emitted in every command output and in `trustkit status --json` (containing `priority`, `target_gate`, `command`, and `description`), consumed by the `trustkit-sdd` skill at the end of every turn.
  - Minimal token consumption and safe schema consumption for agentic parsers.

## 14. Build, Installation & Testing

### Prerequisites
- Rust 1.82+ (2024 / 2021 Edition) and Cargo installed.
- Git 2.38+ (with worktree and sparse-checkout support).
- SQLite 3.35+ (WAL mode support enabled).
- GitHub CLI (`gh`) authenticated (for project boards and PR interactions).

### Build & Verification Commands
```bash
# Clone the repository
git clone git@github.com:mymakecoins/TRustKit.git
cd TRustKit

# Development build
cargo build

# Strict static analysis with zero warning tolerance
cargo clippy --workspace --all-targets --all-features -- -D warnings

# Verify hexagonal isolation of core crate (zero external dependencies)
cargo tree -p trustkit-core

# Execute complete test suite (unit, integration, and E2E)
cargo test --workspace

# Optimized production release build with LTO and binary stripping
cargo build --workspace --release
```

The optimized static binary will be generated at:
```
target/release/trustkit
```
