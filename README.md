# TRustKit

Motor Deterministico em Rust para Governanca de Spec-Driven Development (SDD), Isolamento em Git Worktrees, Gauntlet Loop V2 e Inteligencia de Grafo Estrutural.

"True Rust performance for trusted, spec-driven agentic execution."

[English version](README.en.md)

---

## 1. Visao Geral

O TRustKit e uma plataforma de governanca e execucao deterministica voltada para fluxos de desenvolvimento orientados a especificacoes (Spec-Driven Development - SDD) em ambientes de alta densidade agêntica (Claude Code, Antigravity, Codex) e times de engenharia de software de alta performance.

O projeto resolve os gargalos criticos de abordagens puramente declarativas (skills em Markdown) e harnesses legados em linguagens interpretadas (Python/Node.js):
- Reducao drastica de latencia: substituicao de cold-starts de 300ms a 2.000ms por validacoes nativas em Rust compiladas em release que executam em 1 a 3 milissegundos.
- Eliminacao de alucinacoes de conformidade: validacao mecanica de regras sintaticas, integridade de testes, invariantes e topologia sem depender do julgamento probabilistico de Modelos de Linguagem (LLMs).
- Paralelismo seguro via Git Worktrees: isolamento de multiplos agentes construtores (builders) em arvores de trabalho independentes com suporte a Copy-on-Write (reflink), prevenindo corrupcao de indice e condicoes de corrida.
- Auditoria imutavel via Event Sourcing: persistencia transacional em SQLite em modo WAL (`.trustkit/state.db`) com registro auditavel de cada transicao de estado, evidencia de execucao e hash criptografico BLAKE3.
- Memoria Perene do Projeto: wiki de documentacao viva (`.trustkit/wiki/`) indexada por SQLite FTS5 com busca semantica BM25 e suporte a wikilinks `[[slug]]`.
- Inteligencia de Grafo Estrutural: extracao sintatica AST via Tree-Sitter de nos de codigo e arestas arquiteturais, fatiamento de contexto multi-hop (BFS/DFS), analise de acoplamento de ondas e deteccao de God Nodes.

### O Paradigma Hybrid Rust Core + Thin Skill

O TRustKit opera sob arquitetura hibrida:
- Thin Skill Declarativa: uma camada minima em Markdown (`SKILL.md`) que reside no contexto dos agentes orquestradores para direcionar decisoes de alto nivel sem consumir tokens em demasia nem invalidar o KV-Cache.
- Native Rust Core: o binario estatico `trustkit`, responsavel por 100% das mutacoes de estado, validacao AST de camada 0, congelamento criptografico BLAKE3, extracao de grafos estruturais, provisionamento de Git Worktrees e sincronizacao com GitHub Projects.

## 2. Invariantes Obrigatorios de Governanca

Todas as operacoes gerenciadas pelo TRustKit respeitam estritamente as regras constitucionais:
1. Proibicao absoluta de emojis ou icones graficos em qualquer arquivo, documentacao, saida de terminal ou commit.
2. Proibicao absoluta de trailers de autoria gerados por IA (como `Co-Authored-By` ou `Generated by`).
3. Toda mutacao de estado e validacao de invariantes deve ser realizada exclusivamente pelo binario `trustkit`.
4. Os testes no Gate 4 devem cumprir o ciclo TDD mecanico: fase RED (falha comprovada) obrigatoriamente registrada antes da fase GREEN (sucesso comprovado).
5. Abertura de Pull Request ocorre exclusivamente sob demanda explicita do desenvolvedor humano.
6. Proibicao de pushes diretos a branches protegidas (`main`, `staging`, `develop`) por agentes autonomos (RN-006).

## 3. Arquitetura do Workspace

O repositorio esta estruturado como um Cargo Workspace modular composto por 6 crates especializados sob estrito isolamento hexagonal:

```
TRustKit/
|-- Cargo.toml
|-- crates/
|   |-- trustkit-core/    # Modelos de dominio puros (std only), entidades de ciclo
|   |                     # de vida, grafos estruturais, portas abstratas e casos de uso.
|   |-- trustkit-db/      # Persistencia SQLite WAL (.trustkit/state.db), indices FTS5 BM25,
|   |                     # grafos relacionais com Shrink-Guard e hasher paralelo BLAKE3.
|   |-- trustkit-gh/      # Integracao com GitHub CLI / GraphQL v2 (Projects, Issues,
|   |                     # Pull Requests sob demanda, comentarios e guardiao de identidade).
|   |-- trustkit-ast/     # Extracao de AST Tree-sitter (Rust e TS/JS), analise de acoplamento,
|   |                     # auditoria de assercoes anti-cheat, graph health check e context slicer.
|   |-- trustkit-orch/    # Isolamento de Git Worktrees (reflink), supervisor assincrono Tokio,
|   |                     # servidor MCP nativo e swarm de criticos do Gauntlet.
|   +-- trustkit-cli/     # Parser de linha de comando Clap, Composition Root (bootstrap),
|                         # modos Humano/Agente e despachante semantico de erros POSIX.
|-- docs/                 # PRD, ADRs de arquitetura, analises e relatorios de certificacao.
|-- specs/                # Especificacoes executaveis e tarefas atomicas dos ciclos SDD.
+-- .trustkit/            # Banco de estado SQLite WAL, wiki de memoria viva e relatorios de grafo.
```

## 4. Jornada dos 7 Gates do SDD

O ciclo de vida de desenvolvimento e governado por 7 gates deterministas:

```
[Gate 0] Inicializacao de Sessao e Setup de Identidade
    |
[Gate 1] Context Slicing e Especificacao V2 (spec.md com Mermaid e Gherkin)
    |
[Gate 2] Congelamento Criptografico da Spec (Selo BLAKE3) e Ingestao na Memoria
    |
[Gate 3] Decomposicao Atomica e Planejamento de Ondas DAG com Analise de Acoplamento
    |
[Gate 4] Execucao Paralela em Git Worktrees + Ciclo TDD Estrito (RED -> GREEN)
    |
[Gate 5] Gauntlet Loop V2 (Auditoria AST Camada 0 + Swarm de Criticos Camada 1)
    |
[Gate 6] Certificacao Imutavel, Merge Deterministico e Pull Request sob Demanda
```

### Gate 0: Inicializacao do Ciclo
Valida identidade GitHub, branches, estado da arvore de trabalho e inicializa o ciclo no banco SQLite WAL:
```bash
trustkit init --issue <ISSUE_ID> [--from-prd <CAMINHO_PRD>] [--json]
```

### Gate 1 & 2: Especificacao e Congelamento (Spec Lock)
Inicializa o documento de requisitos (`spec.md`), valida sintaxe Mermaid, cenarios Gherkin e o fechamento da Matriz de Rastreabilidade (RN -> RF -> TASK -> E2E). Ao congelar, sela o documento com BLAKE3 e ingere na memoria perene:
```bash
# Inicializacao da especificacao a partir de PRD ou template
trustkit spec init --issue <ISSUE_ID> [--from-prd docs/PRD.md] [--json]

# Congelamento e selamento criptografico
trustkit spec lock [--json]
```

### Gate 3: Tarefas Atomicas e Planejamento de Ondas DAG
Valida as tarefas em `tasks/TASK-NNN.md`, detecta acoplamento topologico e God Nodes, constroi o grafo direcionado aciclico (DAG) e calcula as ondas de execucao independente:
```bash
trustkit wave plan [--json]
```

### Gate 4: Execucao em Git Worktrees e TDD Estrito
Executa tarefas em paralelo provisionando Git Worktrees efemeras com isolamento de sistema de arquivos e valida o ciclo de testes:
```bash
# Despacho da onda com isolamento de worktree
trustkit wave run --wave <INDICE_ONDA> [--json]

# Registro obrigatorio da fase RED (falha comprovada do teste)
trustkit task test <TASK_ID> --phase red [--json]

# Registro obrigatorio da fase GREEN (sucesso comprovado apos a implementacao)
trustkit task test <TASK_ID> --phase green [--json]

# Conclusao e homologacao da tarefa atomica
trustkit task complete <TASK_ID> [--json]
```

### Gate 5: Gauntlet Loop V2
Auditoria em camadas protegendo contra regressoes, adulteracao de testes e violacoes de codigo limpo:
- Camada 0 (AST Audit estatico em < 5ms): contagem de assercoes de testes antes/depois, varredura de emojis, deteccao de trailers IA, bloqueio de `any` em TypeScript e links externos proibidos.
- Camada 1 (Swarm Concorrente): execucao de linting, build em release, testes ponta a ponta e criticos adversariais.
- Disjuntor (Circuit Breaker): bloqueio de seguranca acionado automaticamente apos 5 reprovacoes consecutivas.

```bash
# Auditoria de Camada 0 (AST e sintaxe)
trustkit gauntlet ast-audit [--json]

# Execucao do Swarm de Criticos da Camada 1
trustkit gauntlet run [--json]

# Diagnostico de falhas e estado do Circuit Breaker
trustkit doctor [--json]
```

### Gate 6: Certificacao, Merge e Pull Request sob Demanda
Consolida as evidencias imutaveis em `gauntlet-report.md`, executa o merge deterministico para a branch alvo e, exclusivamente sob solicitacao humana explicita, abre o Pull Request formatado:
```bash
# Emissao do relatorio oficial de certificacao
trustkit done [--json]

# Merge deterministico para a branch de destino
trustkit merge --target develop [--json]

# Abertura de Pull Request (somente sob demanda humana)
trustkit pr --target develop [--json]
```

## 5. Memoria Perene de Conhecimento (`trustkit memory`)

O subsistema de memoria persistente do TRustKit gerencia a base viva de conhecimento em Markdown com frontmatter estruturado em `.trustkit/wiki/`:

- Indice Full-Text Search (FTS5) no SQLite com ranqueamento BM25 para recuperacao em microssegundos.
- Resolucao de Wikilinks bidirecionais no formato `[[slug]]` ou `[[slug|Alias]]`.
- Ingestao automatizada de incidentes do Gauntlet e especificacoes de produto.
- Subcomandos disponiveis:
  ```bash
  # Busca semantica por termos na wiki
  trustkit memory search --query "invariants policy" [--limit 5] [--json]

  # Leitura de nota com metadados e links adjacentes
  trustkit memory read --slug "architecture-decision" [--json]

  # Criacao ou atualizacao atomica de nota
  trustkit memory write --slug "novos-padroes" --title "Novos Padroes" --tags "core,guidelines" --body "Conteudo..." [--json]

  # Listagem de todas as notas da base
  trustkit memory list [--json]

  # Reconstrucao completa do indice FTS5 a partir dos arquivos em disco
  trustkit memory reindex [--json]
  ```

## 6. Inteligencia de Grafo Estrutural (`trustkit graph`)

O motor de grafo extrai e mantem a topologia completa de dependencias de codigo e documentacao do repositorio:

- Extracao sintatica via Tree-Sitter para Rust (modulos, structs, traits, enums, funcoes publicas e use declarations) e TypeScript/JavaScript (exports, imports, interfaces, classes e funcoes).
- Unificacao do grafo de codigo com o grafo de conhecimento da wiki (`[[slug]]`).
- Classificacao tipada de relacoes: `Calls`, `Imports`, `Defines`, `Implements`, `WikiLinksTo` com confiabilidade `Extracted` ou `Inferred`.
- Mecanismo Shrink-Guard com manifesto BLAKE3 para impedir reducao acidental de nos sem flag `--force`.
- Subcomandos disponiveis:
  ```bash
  # Constroi ou atualiza o grafo estrutural e emite .trustkit/wiki/graph/GRAPH_REPORT.md
  trustkit graph build [--force] [--update] [--json]

  # Audita a saude do grafo, identifica God Nodes e violacoes de fronteiras arquiteturais
  trustkit graph health [--top-god-nodes 10] [--json]

  # Encontra o caminho minimo (menor numero de saltos) entre dois simbolos via BFS
  trustkit graph path --source "src/lib.rs::SddCycle" --target "crates/trustkit-db::SqliteWalRepositoryAdapter" [--undirected] [--json]

  # Explica a vizinhanca de conexoes, dependencias e notas wiki de um no especifico
  trustkit graph explain --node "crates/trustkit-core/src/entities.rs::SddCycle" [--json]
  ```

## 7. Context Slicing e Fast Hooks

### Context Slicing Guiado por Grafo e AST
Permite fatiar cirurgicamente trechos relevantes de codigo para nutrir prompts agênticos sem estourar janelas de contexto:
```bash
# Fatiamento classico por arquivo com orcamento de linhas/tokens
trustkit context slice --file crates/trustkit-core/src/lib.rs --budget 500 [--json]

# Fatiamento multi-hop guiado pelo grafo estrutural (BFS ou DFS)
trustkit context slice --file crates/trustkit-core/src/entities.rs --hops 2 --strategy bfs --budget 600 [--json]
```

### Pre-Tool e Post-Tool Fast Hooks (< 3ms)
Interceptam ferramentas de agentes em tempo real para impedir acoes destrutivas antes da execucao:
```bash
trustkit hook pre-tool --command "<COMANDO>" [--json]
```
Bloqueia automaticamente:
- Comandos destrutivos de Git (`git stash`, `git reset --hard`, `git clean -fd`).
- Adicoes genericas de stage (`git add .`, `git add -A`).
- Tentativas de push direto a branches protegidas (`git push origin develop`).
- Abertura autonoma de PRs sem invocacao de `trustkit pr`.
- Presenca de emojis Unicode ou trailers de autoria IA em commits.

## 8. Servidor Model Context Protocol (MCP) Nativo

O TRustKit disponibiliza um servidor MCP nativo via stdio para integracao direta com Claude Code, Cursor, Antigravity e ambientes agênticos compativeis:

```bash
trustkit mcp
```

### Ferramentas MCP Expostas:
- `trustkit_cycle_status`: Consulta o estado do ciclo ativo, gate atual e saude da esteira.
- `trustkit_context_slice`: Executa o fatiamento de contexto AST e multi-hop de arquivos e simbolos.
- `trustkit_memory_search`: Busca textual na memoria perene com ranqueamento BM25.
- `trustkit_memory_read`: Leitura de notas wiki e seus links bidirecionais.
- `trustkit_memory_write`: Gravacao e sincronizacao de novos documentos de conhecimento.
- `trustkit_graph_query`: Consulta nos e relacoes do grafo por filtros de camada e tipo.
- `trustkit_graph_path`: Determina o caminho estrutural entre dois simbolos.
- `trustkit_graph_explain`: Analisa vizinhanca estrutural e acoplamentos de um no.
- `trustkit_graph_health`: Relata metricas de saude, God Nodes e arestas pendentes.

## 10. Codigos de Saida Semanticos (POSIX Exit Codes)

| Codigo | Identificador | Categoria | Descricao |
|---|---|---|---|
| 0 | CleanPass | Sucesso | Operacao concluida com aprovacao integral em todos os gates. |
| 1 | InfrastructureBoundaryFault | Falha de Infraestrutura | Erro de I/O de disco, SQLite WAL, subprocessos Git ou rede. |
| 2 | SpecOrTraceabilityIncomplete | Falha de Especificacao | Spec nao congelada, sintaxe Mermaid/Gherkin invalida ou lacuna na matriz. |
| 3 | TddLifecycleViolation | Infracao de TDD | Tentativa de GREEN sem RED comprovado ou quebra de fluxo TDD. |
| 4 | AstIntegrityOrInvariantViolation | Violacao de Invariantes | Emojis detectados, trailers de IA, ciclos no DAG ou adulteracao de assercoes. |
| 5 | CriticSwarmOrPlaywrightFailed | Reprovacao no Gauntlet | Falha de compilação, linter, reprovacao em testes E2E ou parecer de critico. |
| 6 | CircuitBreakerTripped | Disjuntor Acionado | Disjuntor disparado apos 5 falhas consecutivas no Gauntlet. |

## 11. Dual-Audience: Modos de Operacao

- Modo Humano (saida padrao em terminal TTY):
  - Interface textual em ASCII puro, sem emojis ou caracteres decorativos.
  - Prefixos padronizados: `[GATE-0]` a `[GATE-6]`, `[PASS]`, `[FAIL]`, `[WARN]`, `[INFO]`.
  - Tabelas alinhadas e resumos executivos objetivos.

- Modo Agente (`--json` ou via `TRUSTKIT_AGENT_MODE=1`):
  - Saida estrita em JSON deterministico e sem formatacoes superfluas.
  - Payloads 100% livres de campos `null` (arrays vazios `[]` e tipos Special Case explicitos).
  - Economia maxima de tokens e integracao segura com parsers agênticos.

## 12. Compilacao, Instalacao e Testes

### Pre-requisitos
- Rust 1.82+ (Edicao 2024 / 2021) e Cargo instalados.
- Git 2.38+ (com suporte a worktrees e sparse-checkout).
- SQLite 3.35+ (modo WAL habilitado).
- GitHub CLI (`gh`) autenticado (para transicoes de board e PRs).

### Compilacao e Validacao
```bash
# Clonar o repositorio
git clone git@github.com:mymakecoins/TRustKit.git
cd TRustKit

# Compilacao em modo desenvolvimento
cargo build

# Verificacao estatica e linter com zero tolerancia a warnings
cargo clippy --workspace --all-targets --all-features -- -D warnings

# Verificacao de isolamento hexagonal do core (zero dependencias externas)
cargo tree -p trustkit-core

# Execucao da suite de testes completa (unitarios, integracao e E2E)
cargo test --workspace

# Compilacao de release otimizada com LTO e strip
cargo build --workspace --release
```

O executavel estatico gerado estara localizado em:
```
target/release/trustkit
```
